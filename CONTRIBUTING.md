# Contributing

Thank you for contributing to a Community Housing Limited repository.

## Before you start

- Follow any repository-specific contribution guidance first.
- Do not commit passwords, credentials, tokens, certificates, private keys, customer information or other sensitive data.
- Use an issue, work item or agreed change record where the repository requires one.
- Keep changes focused and appropriately scoped.
- Update documentation when behaviour, configuration or operating procedures change.

## Branches and commits

Use descriptive branch and commit names that make the purpose of the change clear.

Prefer small, reviewable commits over large unrelated changes.

## Pull requests

A pull request should:

- explain what is changing and why;
- identify relevant risk or operational impact;
- describe how the change was validated;
- identify security, privacy or data considerations;
- include deployment and rollback information when applicable; and
- reference the relevant issue, work item or change record when one exists.

Do not merge your own change where repository rules require independent approval.

## Testing

Run the appropriate tests, validation or checks for the repository before requesting review. If automated tests do not exist, document the manual validation performed.

## Security

Do not use a public issue to report a suspected security vulnerability. Follow `SECURITY.md`.

## Repository-specific requirements

A repository may define stricter contribution, testing, review or deployment requirements. Those repository-specific requirements take precedence over this default.
