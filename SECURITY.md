# Security

Security vulnerabilities must not be reported through public GitHub issues, discussions or pull requests.

## CHL team members

Use CHL's approved internal IT and security incident/reporting channels.

If a repository has specific security reporting instructions, follow those instructions first.

## External reporters

Where GitHub Private Vulnerability Reporting is enabled for the affected repository, use that mechanism.

If no private repository reporting mechanism is available, contact CHL through https://chl.org.au/contact/ and request an appropriate secure channel before sending sensitive technical or exploit details.

## Sensitive information

Do not include passwords, tokens, private keys, customer information, personal information, production data or other sensitive material in issues, pull requests, logs or screenshots.
